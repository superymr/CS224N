# 大模型科研入门：第一批核心术语

> 分类：人工智能 / 大模型 / 科研入门
> 主题：Token、Embedding、Transformer、训练、微调、推理、RAG 与评测

## 学习目标

- 建立大模型领域的基础术语地图。
- 理解文本如何进入模型、模型如何训练以及结果如何生成。
- 区分预训练、监督微调、LoRA、对齐、RAG 和评测。
- 为后续阅读论文、复现实验和提出研究问题准备基础词汇。

## 一、整体链路

大模型可以先用下面两条链路理解：

```text
文本 → Tokenizer → Token ID → Embedding → Transformer/Attention
     → 预测下一个 Token → Inference → 生成回答
```

模型能力通常经历以下阶段：

```text
预训练模型 → SFT/LoRA → RLHF/DPO → RAG/工具调用 → 推理与评测
```

## 二、Token 与 Embedding

### 1. Token

`Token` 是模型处理文本的基本单位。它可能是：

- 一个汉字；
- 一个中文词语或短语；
- 一个英文单词或子词；
- 单词的一部分；
- 代码中的关键字、符号或其他片段。

Token 不一定等于汉字或完整单词。具体切分方式由 `Tokenizer`、词表和预处理规则决定。

### 2. Tokenizer 与 Token ID

`Tokenizer` 将文本转换为 Token 序列，再转换为整数形式的 `Token ID`：

```text
人类文本
  ↓ Tokenizer
Token 片段
  ↓ 查词表
Token ID
```

在同一个模型中，使用相同的 Tokenizer、词表、预处理规则和特殊 Token 配置时，某个 Token 对应的 ID 通常是固定的。但文本具体如何切分，可能受 Tokenizer 规则和上下文影响。

不同模型之间的 Token ID 通常不可直接互换。即使两个模型出现相同的数字，也不能据此判断它们代表相同的 Token。

Token 数量会影响：

- 上下文窗口占用；
- 推理速度；
- API 或计算成本；
- 模型能否容纳一段长文本。

### 3. Embedding

Token ID 只是编号，本身没有语义。例如：

```text
猫 → 100
狗 → 101
飞机 → 102
```

这些编号不表示词语之间的相似程度。模型会通过 Embedding 矩阵将 Token ID 映射为连续向量：

```text
Token ID 582
  ↓
Embedding 矩阵第 582 行
  ↓
[0.12, -0.45, 0.88, ...]
```

Embedding 矩阵的形状通常可以表示为：

```text
词表大小 × 向量维度
```

Embedding 向量会参与神经网络计算，并通过训练不断更新。

### 4. Token Embedding、Hidden State 与文本 Embedding

需要区分三类概念：

- `Token Embedding`：单个 Token 的初始向量；
- `Hidden State`：结合上下文后得到的动态语义表示；
- `Text/Sentence Embedding`：将一段文本转换为向量，常用于语义搜索、聚类和 RAG。

例如“银行”在“我去银行取钱”和“河流的银行很陡”中可能有不同含义。两句话中的初始 Token Embedding 可以相同，但经过 Transformer 和 Attention 后，得到的上下文表示会不同。

### 5. 语言与 Tokenizer

Token 不是一种独立的自然语言，也不是完整的“模型语言”。它是经过编码的文本碎片。

Token 可以跨语言使用，但具体 Tokenizer 和词表会受训练语料、语言结构和编码设计影响：

- 中文可能按单字、词语或短语切分；
- 英文单词可能被拆成多个子词；
- 代码中的符号、关键字和缩进可能分别成为 Token；
- 同一段文本在不同模型中可能产生不同数量的 Token。

更准确的表述是：**Token 是跨语言的编码单位，但具体 Tokenizer 和词表具有语言倾向性。**

## 三、Transformer 与 Attention

### 1. Transformer

`Transformer` 是当前主流大语言模型的核心架构，主要由以下模块构成：

- `Self-Attention`；
- `Feed-Forward Network`；
- 残差连接；
- `Layer Normalization`；
- 位置编码。

多个 Transformer Block 通常会堆叠起来，形成完整模型。

### 2. Attention

`Attention` 让模型根据上下文动态决定当前 Token 应该重点关注哪些 Token。

例如：

```text
小明把书放在桌子上，因为他要去上课。
```

模型需要判断“他”更可能指向“小明”。Attention 可以帮助模型建立这种上下文关系。

Attention 的基本形式为：

```text
Attention(Q, K, V) = softmax(QKᵀ / √d) V
```

- `Q`（Query）：当前 Token 想寻找什么；
- `K`（Key）：每个 Token 能提供什么线索；
- `V`（Value）：实际被聚合和传递的信息。

可以把 Attention 理解成一次带权重的信息检索：先计算相关性，再根据相关性聚合信息。

### 3. Self-Attention 与 Causal Attention

`Self-Attention` 表示序列中的 Token 彼此计算相关性。

生成式大模型通常使用 `Causal Self-Attention`：当前位置只能看到自己和之前的 Token，不能偷看未来 Token。这保证了训练目标和实际生成过程一致。

## 四、预训练与监督微调

### 1. Pretraining

`Pretraining` 使用海量文本训练模型预测下一个 Token：

```text
输入：北京是中国的
预测：首都
```

训练过程通常包括：

1. Tokenizer 将文本转换为 Token；
2. 模型预测下一个 Token 的概率；
3. 将预测结果与真实 Token 比较；
4. 计算 Loss；
5. 反向传播并更新参数。

预训练使模型获得语言、知识、代码和模式归纳等通用能力，但预训练模型不一定善于遵循用户指令。

### 2. SFT

`SFT`（Supervised Fine-Tuning，监督微调）使用指令—回答样本继续训练模型：

```text
指令：解释什么是牛顿第二定律
回答：牛顿第二定律指出……
```

SFT 主要让模型学会：

- 理解用户指令；
- 按要求回答；
- 遵守输出格式；
- 进行多轮对话。

核心区别是：

```text
预训练：学会语言和一般模式
SFT：学会按照指令完成任务
```

## 五、LoRA、RLHF 与 DPO

### 1. LoRA

`LoRA` 是一种参数高效微调方法。它冻结原始模型，只训练少量低秩增量参数：

```text
新权重 = 原始权重 + 低秩增量
```

优点包括：

- 显存占用较低；
- 训练成本较低；
- 可以为不同任务保存不同 Adapter；
- 原始基础模型可以复用。

LoRA 更像“专业技能插件”，而不是知识库。它可以让模型形成某种领域能力、语言风格或行为倾向，但不适合作为需要实时更新和可追溯的事实数据库。

### 2. RLHF

`RLHF`（Reinforcement Learning from Human Feedback）通过人类偏好优化模型：

```text
人类偏好数据 → 奖励模型 → 强化学习优化语言模型
```

例如让人类判断同一问题的两个回答哪个更好，模型据此学习更符合人类偏好的回答方式。

### 3. DPO

`DPO`（Direct Preference Optimization）直接利用偏好数据进行优化，通常不需要完整执行传统 RLHF 的强化学习流程。

典型数据格式为：

```text
Prompt
Chosen Answer
Rejected Answer
```

粗略而言：

- RLHF 流程更复杂，但表达能力较强；
- DPO 实现更简单、训练通常更稳定，应用广泛。

## 六、Inference 与生成参数

`Inference` 是使用训练好的模型生成结果的过程。模型通常逐个 Token 生成文本：

```text
机器 → 学习 → 是 → 一种 → ……
```

常见生成参数：

- `temperature`：控制随机性。低温度更稳定，高温度更多样；
- `top-k`：只从概率最高的 k 个 Token 中采样；
- `top-p`：从累计概率达到 p 的候选集合中采样；
- `max_new_tokens`：限制最多生成多少新 Token。

## 七、语义搜索与 RAG

### 1. 语义搜索

语义搜索不只匹配字面关键词，而是将问题和文档转换为向量，再根据语义相似度检索内容：

```text
文本 → Embedding 向量 → 相似度计算 → 返回相关内容
```

### 2. RAG

`RAG`（Retrieval-Augmented Generation，检索增强生成）将检索系统与大语言模型结合：

```text
用户问题 → 检索相关文档 → 将文档放入 Prompt → 大模型生成回答
```

语义搜索负责“找到相关资料”，RAG 负责“让大模型利用资料回答”。RAG 可以接入最新知识、企业内部资料和个人知识库，减少重新训练模型的需求，但不能自动保证检索内容或最终回答一定正确。

### 3. RAG 的典型组成

- `Chunking`：文档切分；
- `Embedding Model`：文本向量模型；
- `Vector Database`：向量数据库；
- `Retriever`：检索器；
- `Reranker`：重排序模型；
- `Context`：提供给大模型的上下文。

完整流程为：

```text
文档 → 文档切分 → Embedding → 向量数据库 → 语义检索
     → 重排序 → 大模型生成答案
```

### 4. RAG、Prompt、SFT 与 LoRA 的区别

- `Prompt`：当前任务的操作指南；
- `SFT`：用大量示例训练模型完成任务；
- `LoRA`：训练少量参数，使模型长期形成某种领域能力或风格；
- `RAG`：回答时检索外部知识。

实际系统经常组合使用：

```text
基础模型 + LoRA 专业能力 + RAG 最新知识
```

## 八、Benchmark 与 Hallucination

### 1. Benchmark

`Benchmark` 是用于比较模型能力的标准化数据集或测试集合，可能覆盖：

- 数学推理；
- 代码生成；
- 知识问答；
- 长文本理解；
- 多语言能力；
- 安全性和鲁棒性。

阅读论文中的评测结果时，应关注：

- 测试任务是否适合研究目标；
- 使用了什么指标；
- 测试数据是否可能泄漏；
- 是否存在训练数据污染；
- 是否使用了额外提示词；
- 是否同时进行了人工评测。

### 2. Hallucination

`Hallucination` 指模型生成看似合理、实际上错误、虚构或缺乏证据的内容。

常见原因包括：

- 模型目标是生成高概率文本，不是自动保证事实真实；
- 训练数据中存在错误；
- 模型缺少相关知识；
- 问题信息不足；
- 模型过度迎合用户；
- 长上下文中忽略了关键证据。

减少幻觉的常见方法包括：

- 使用 RAG；
- 使用搜索、数据库或其他工具查询；
- 要求模型提供证据；
- 进行事实核验；
- 允许模型表达不确定性；
- 设计专门的可靠性评测。

## 九、关键总结

1. `Token` 是文本切分后的离散片段，`Token ID` 是词表中的编号。
2. `Embedding` 将 Token ID 映射为可计算的向量。
3. `Transformer` 是大语言模型的主要架构，`Attention` 是其核心机制。
4. `Pretraining` 让模型获得通用能力，`SFT` 让模型学会遵循指令。
5. `LoRA` 是低成本微调方法，不是新的基础模型。
6. `RLHF` 和 `DPO` 用偏好数据改善模型行为。
7. `Inference` 是使用模型生成结果的过程。
8. `RAG` 是外部知识检索增强，不等于重新训练模型。
9. `Benchmark` 用于评测模型能力，但单一指标不能代表模型全部能力。
10. `Hallucination` 是大模型可靠性研究中的重要问题。

## 十、下一步学习建议

下一阶段建议重点学习：

1. `Attention(Q, K, V)` 的具体计算过程；
2. Transformer Block 的完整结构；
3. 预训练、SFT 和 DPO 的训练目标；
4. LoRA 的矩阵形式和参数量计算；
5. RAG 中的 Chunking、Retriever 与 Reranker；
6. 如何设计一个可复现的大模型评测实验。
